# Xenium-Bering benchmark configuration

The runtime is the Bering conda environment:

```bash
for c in yourpath/bering/configs/*.json; do
  yourpath/anaconda3/envs/bering/bin/python \
    yourpath/bering/bering_xenium_benchmark.py --config "$c" --check
done
```

After confirming all inputs, run once per config:

```bash
yourpath/anaconda3/envs/bering/bin/python \
  yourpath/bering/bering_xenium_benchmark.py \
  --config yourpath/bering/configs/xenium_breast.json
```

## xenium7 and xenium_8 (center 10000x10000 px)

The one-click background launcher for both datasets is:

```bash
yourpath/bering/run_bering_xenium_center10000.sh
```

The script runs `--check` first, then runs xenium7 and xenium_8 in order via
`nohup`, to avoid occupying GPU 6 that the benchmark runner uses exclusively.
Logs are in `yourpath/bering/logs/`; output directories are
`xenium7_center10000_output/` and `xenium_8_center10000_output/`.
Set `BERING_DRY_RUN=1` to only pre-check without submitting jobs.

| Config | ROI (native px) | Notes |
|---|---|---|
| xenium_breast | center 5000x5000 | x0=24497, y0=11210 |
| xenium_roi_crop | full pre-cropped dataset | 3982.5-4317.5 x 2522.5-2857.5 um |
| xenium_liver | center 10000x10000 | x0=19470, y0=11200 |
| xenium_mouse_brain | center 10000x10000 | x0=12077, y0=6956 |
| xenium_colon | center 10000x10000 | x0=9241, y0=12052 |
| xenium_pancreas_cancer | full valid transcript range | the sixth dataset in the original script; its ROI was not provided |

All configs use: `qv >= 20`, `is_gene == True` (when the field exists), the same
control-prefix filtering, 2-D coordinates, the same Bering hyperparameters, and
random seed 0. Bering's `raw_cells` come from the official Xenium
`transcripts.cell_id`; these are therefore **reference-assisted** results and
must not be labeled a fair de-novo comparison against prior-free methods.
`cell_boundaries.parquet` is never used as a prediction input. Training labels
are generated by a fixed MiniBatchKMeans over the expression matrix inside the
training sub-tile, so no dataset uses extra manual annotation.

If the paper compares "reference-free" methods, list Bering separately as
reference-assisted, or provide the same prior to all methods; do not merge the
`cell_groups.csv` label-supervised results into a ranking with unlabeled
methods. ROI, QC, post-processing thresholds, and tile-stitching radius must
all remain unchanged.

## Baysor evaluation

The evaluation script for official Xenium segmentation as GT and
`yourpath/baysor/xenium_*_output` as predictions is:

`yourpath/cellseg_benchmark/code/baysor/evaluate_code/baysor_value_xenium.py`

The script computes cell detection (precision/recall/F1), centroid shift,
matched-cell transcript counts and gene-vector consistency following
`ucs_value_xenium_4&5&6.py`, plus the transcript-assignment accuracy of `cell_id`
in the official `transcripts.*`. Baysor's `segmentation.csv` uses global
micrometre coordinates and is read in chunks during evaluation to avoid loading
large files at once. Although Baysor ran on the center 15000x15000 native-px
region for `xenium_liver`, evaluation only compares the center 10000x10000
native-px sub-region (x[21974,31974), y[13704,23704)) per the official
`central_roi_10000/gt_roi_info.json`.

```bash
python yourpath/cellseg_benchmark/code/baysor/evaluate_code/baysor_value_xenium.py \
  --dataset breast --out-dir yourpath/eval_results/baysor_xenium

# evaluate five datasets at once (using the built-in Baysor ROI and paths)
python yourpath/cellseg_benchmark/code/baysor/evaluate_code/baysor_value_xenium.py --all --out-dir yourpath/eval_results/baysor_xenium
```

Each dataset produces `*_sparse_hungarian_qc_metrics_full.csv`,
`*_sparse_hungarian_qc_metrics_selected.csv`, and the matched-cell details;
`--qv-min 0` disables quality-value filtering, and `--match-radius` overrides the
default GT nearest-neighbor p95x1.25 match radius.

## Baysor-MERFISH evaluation

The MERFISH Baysor evaluation script is
`yourpath/cellseg_benchmark/code/baysor/evaluate_code/baysor_value_merfish.py`.
It uses cell centers from the official Vizgen `cell_metadata.csv` as GT and the
exact same sparse Hungarian cell matching and metric columns as the Xenium
evaluation:

```bash
python yourpath/cellseg_benchmark/code/baysor/evaluate_code/baysor_value_merfish.py \
  --all --out-dir yourpath/eval_results/baysor_merfish
```

MERFISH's raw `detected_transcripts.csv` has no official per-transcript `cell_id`.
For liver1, liver2 and mouse_brain, the script reads the existing
`transcripts_roi_with_prior.csv.gz` (generated from the official cell-boundary
polygons) as a per-transcript proxy label, and keeps transcript counts, gene
vectors and assignment accuracy in the results. For lung, prostate1 and
prostate2, run the preparation script below to generate the same format, then the
same transcript-level metrics can be computed.

To generate same-format GT transcript files for lung, prostate1 and prostate2:

```bash
python yourpath/cellseg_benchmark/code/baysor/evaluate_code/prepare_merfish_gt_transcripts.py \
  --all
```

The script reads each dataset's official `cell_boundaries/*.hdf5` polygons and
writes a `cell_id` for transcripts on a 1-um grid within the corresponding
10000x10000 ROI, defaulting to
`yourpath/baysor/merfish_gt_tx/<dataset>/transcripts_roi_with_prior.csv.gz`.
After generation, simply re-run the Baysor evaluation command above to use these
labels automatically, or use `--gt-transcripts` to point to a single file. The
`cell_id` is an ROI-local label produced by boundary rasterization; the evaluation
script bridges it to official `cell_metadata.csv` IDs via cell centers.
